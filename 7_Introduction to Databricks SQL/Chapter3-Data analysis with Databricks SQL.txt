Supplementing queries with functions
Queries, like the one we created in the last exercise, often start off as basic data retrieval
from our source tables. In this exercise, we will expand on this query and, using different
functions, gain more insight our query results.

1. Open your query "Insurance Claim Analysis" from the previous exercise.
If you can't find this, open the query "ex_ch3_5_supplementing_queries_with_functions" from 
the Queries section.

2. Assuming these are each customer's first claims, we want to ensure timely and sufficient support.
    Using the date_diff function, update the existing query to include the following new fields:
        "CustomerMonths", as the number of months between the POLICY_EFF_DT and REPORT_DT fields.
        "PaymentDays", as the number of days between the REPORT_DT and TXN_DATE_TIME fields.

3. These metrics help identify customer groups with varying churn risk, which is the 
likelihood that a customer will stop doing business with the company. Newer customers 
with longer payment delays may be more likely to churn, and vice versa.

Update the query to include a new field, called "ChurnRisk", which uses the 
CustomerMonths and PaymentDays as evaluation criteria.

SELECT 
    CUSTOMER_ID,
    PREMIUM_AMOUNT,
    CLAIM_AMOUNT,
    POLICY_EFF_DT,
    REPORT_DT,
    TXN_DATE_TIME,
    INSURANCE_TYPE,
    HOUSE_TYPE,
    INCIDENT_STATE,
    INCIDENT_SEVERITY,
    date_diff(MONTH, POLICY_EFF_DT,REPORT_DT) AS `CustomerMonths`,
    date_diff(DAY, report_dt, TXN_DATE_TIME) AS `PaymentDays`,
    CASE 
        WHEN CustomerMonths <= 12 AND PaymentDays > 30 THEN 'High'
        WHEN CustomerMonths > 12 AND PaymentDays <= 30 THEN 'Low'
    ELSE 'Medium' END AS `ChurnRisk`
FROM insurance
WHERE INCIDENT_SEVERITY != 'Minor Loss'

4. Which of the following statements best summarizes the purpose of the functions we used in this query?
R:We calculated specific KPIs on customer response time using date_diff, and we used the CASE statement to compare specific criteria and put customers into different "buckets" based on risk.
